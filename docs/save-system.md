# 進行データのオートセーブ

## 保存対象

- 一騎モードの最高解放レベル
- 解放済み特殊札数
- 一騎モードのクリア状態（バトルグラウンド解放）
- バトルグラウンドの最高連勝記録

対戦中の手札・ライフ・選択中の特殊札・現在の連勝数は保存しない。
ゲームを起動し直すと対戦は最初から開始し、解放状況と最高記録を復元する。

## 保存タイミングと接続先

`GameProgressStore` が起動時に読み込み、未保存・旧形式・補正が必要なデータを自動保存する。
`GameSessionFlow.RunMode` は勝利確定後、リザルト画面の操作待ちに入る前に
`RecordIkkiVictory` または `RecordBattleGroundStreak` を呼ぶ。
各更新で `PlayerPrefs.Save()` まで実行するため、手動のセーブ操作や終了イベントに依存しない。
敗北・中断・以前より低い記録によって進行は後退しない。

## 保存形式と復旧

`PlayerPrefsProgressRepository` を通して端末内の PlayerPrefs に保存する。

| キー | 内容 |
| --- | --- |
| `EfudaIkki.Progress` | スキーマ2の進行JSON |
| `EfudaIkki.Progress.Backup` | 最新保存時の同じJSON（復旧用） |
| `EfudaIkki.IkkiCleared` | 旧形式との互換用クリアフラグ |
| `EfudaIkki.BestKachinukiStreak` | 旧形式との互換用最高連勝数 |

主データが欠落・不正な場合は、バックアップ、旧形式キー、初期値の順で復旧する。
欠落フィールドや範囲外の値は補正し、同じ状態が揃っていれば書き込みを繰り返さない。
将来バージョンのJSONは既知の項目だけ読み、通常の更新で上書きしようとすると例外で保護する。
保存失敗は呼び出し元へ通知し、次回の読み込み・更新でフラッシュを再試行する。

`ResetProgress()` は明示的な初期化用API。バックアップと旧形式キーも初期化し、
復旧時に削除済みの進行が復活しないようにする。初期化ボタンのUIは追加していない。

バックアップは同じ PlayerPrefs 内にあり、PlayerPrefs 全体の削除・破損には対応しない。
クラウド同期や端末間移行は対象外。

## テスト

Unity Test Runner の EditMode で以下を実行する。

- `GameProgressStoreTests`: 保存後の再起動を模擬するリポジトリ、破損復旧、移行、初期化、
  単調な進行、書き込み抑制、不正レベル、将来バージョン保護、保存失敗後の再試行。
- `ProgressAutoSaveIntegrationTests`: 実際の PlayerPrefs アダプター、起動処理、
  一騎・バトルグラウンドの勝利から保存までのフロー、敗北・中断。

実ストレージのテストは毎回固有の `EfudaIkki.Tests.*` 接頭辞を使い、そのキーだけを後片付けする。
ユーザーの本番データを初期化しない。対戦フローのテストは対戦完了を境界で模擬し、
リザルト表示前に保存されることを検証する。OSプロセスの再起動テストは含まない。
